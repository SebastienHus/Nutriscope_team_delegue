=========================================================
NUTRISCOPE
MODELE DE DONNEES RELATIONNEL (3FN)
VERSION 1
=========================================================

OBJECTIF

Transformer le dataset Open Food Facts sélectionné
en une base relationnelle normalisée respectant
au maximum la troisième forme normale (3FN).

Les données multi-valuées (tags, listes, tableaux)
sont externalisées dans des tables dédiées avec
tables de liaison.

Les données calculables ou dérivables ne sont pas
dupliquées.

Le modèle privilégie :

- la cohérence des données ;
- la réduction des redondances ;
- la facilité d'évolution ;
- la conformité à la 3FN ;
- l'exploitation analytique via SQL.


=========================================================
DECISION D'ARCHITECTURE : CATEGORIES
=========================================================

Aucune table MAIN_CATEGORY n'est conservée.

Raison :

Dans Open Food Facts, la catégorie principale est
une information dérivable de la hiérarchie des
catégories.

Stocker simultanément :

- main_category
- categories_tags

créerait une redondance.

Afin de respecter la 3FN :

- une seule table CATEGORY est conservée ;
- les relations parent/enfant permettent
  de reconstruire l'arbre des catégories.

Exemple :

foods
└── dairy-products
    └── yogurts
        └── drinkable-yogurts

La catégorie principale peut être retrouvée
par parcours hiérarchique.


=========================================================
DECISION D'ARCHITECTURE : NUTRITION
=========================================================

La modélisation de type EAV :

type_nutrition
nutrition

a été abandonnée.

Motifs :

- augmentation très importante du nombre de lignes ;
- requêtes plus complexes ;
- agrégations nutritionnelles plus coûteuses ;
- difficulté de lecture.

La table NUTRITION contient donc directement
l'ensemble des indicateurs nutritionnels d'un produit.

Cette modélisation reste conforme à la 3FN :

code_produit
    ->
toutes les valeurs nutritionnelles

car aucune colonne nutritionnelle ne dépend d'une autre.

TABLE : category
=========================================================

Description :

Hiérarchie complète des catégories Open Food Facts.

Colonnes :

id_category (PK)

category_tag

parent_category_id (FK nullable)

Exemple :

id | category_tag           | parent_category_id
----------------------------------------------------
1  | en:foods               | NULL
2  | en:dairy-products      | 1
3  | en:yogurts             | 2
4  | en:drinkable-yogurts   | 3
